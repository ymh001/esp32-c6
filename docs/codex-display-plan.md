## 目标与第一版范围

将 ESP32-C6 屏幕作为 Codex 状态副屏，显示账户剩余额度、任务状态与完成提醒。
第一版包括额度卡片、当前任务状态、完成提醒和可滑动的任务列表。
保留现有时钟、手动设备控制和耗电功能，新增 Codex 页面。

## 推荐架构

```text
Mac 上的 Codex → Mac 本地桥接程序 → USB 串口 → ESP32 屏幕
```

- Mac 桥接程序负责读取额度与任务状态，规范化为简短的数据消息。
- ESP32 负责消息解析、状态缓存、页面展示和连接状态提示。
- 优先 USB：同时供电和传输，不受 WiFi 定时关闭影响。
- 刷机时桥接程序必须释放串口，刷机结束后自动重连；需要验证串口重连不会
  误触发复位，避免影响现有烧录流程。
- 第一版不依赖 NAS。以后需要无线或外网查看，再评估网络转发。
- Codex 登录凭据留在 Mac；屏幕只接收展示所需数据。

## 数据来源与限制

### 账户额度

官方 App Server 协议提供 `account/rateLimits/read` 和
`account/rateLimits/updated`，包含 `usedPercent`、`windowDurationMins`、
`resetsAt` 等信息。

- 剩余百分比按 `100 - usedPercent` 计算并限定在 0–100。
- 窗口名称按实际时长生成，不能固定假定始终存在五小时和每周两个窗口。
- 多额度桶时保留其身份，避免混淆不同额度。
- 显示重置时间或倒计时；字段缺失显示“暂不可用”，不能当成 0%。
- 展示的是账户共享额度，不是单个任务剩余预算。

### 任务状态与进度

可评估的官方事件包括 `thread/status/changed`、`turn/completed`、
`turn/plan/updated` 和任务条目事件。

展示字段建议：任务名称、运行中/等待用户处理/本轮完成/失败、当前步骤、
已运行时间、最后更新时间。

- 有明确计划时显示“完成 3/5 步”；无计划时只显示状态和当前阶段。
- 不根据耗时编造完成百分比。
- 本轮执行结束与整个项目完成应区分；中断、失败不能显示为成功完成。
- 多任务列表可滑动，待处理和新完成的任务可优先提示。

### 实施前必须验证的接入问题

官方 App Server 有上述协议，不代表独立启动一个服务就能收到现有桌面应用
全部任务的实时事件。首先验证当前桌面版本能否提供可用的只读状态接入。
必要时评估本地会话记录作为补充，并注明版本兼容限制。

不能把无日志更新、连接断开或任务未加载推断为完成，也不能为了观察任务
而恢复、启动或改变原任务。现有会话中的应用工具不应直接假定为独立后台
程序可以调用的公共接口。

## 与省电模式的配合

- USB 副屏模式：持续接收状态，保持亮屏，CPU 继续 40–160 MHz 动态调频。
- 任务完成或等待确认时显示提示卡片；避免每条日志都触发提醒。
- Mac 休眠或通信超时：显示“连接已断开”及最后更新时间，随后按息屏设置休眠。
- 后续 WiFi 副屏模式若需要实时提醒，就需要保持连接；退出副屏模式后恢复
  原有全局定时同步策略。不能承诺 WiFi 关闭期间仍能立即收到推送。
- 通信应有心跳、消息长度上限、版本号和重连后的完整状态同步，防止旧缓存
  被误当作当前状态。
