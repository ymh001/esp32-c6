# v0.2.4 验证记录（2026-09-27）

## 已实现

控制中心独立文件传输开关、设备地址与临时访问码。网页支持当前目录上传、子目录浏览、
下载、删除及取消；单文件上限 128 MB，重启默认关闭。只通过 main 任务访问 SD，
HTTP 任务经队列提交 1 KB 文件作业，不调用 LVGL；管理任务停止 HTTP 服务避免 UI 死锁。

保留 Wi-Fi / Grafana 凭据与 NVS；应用镜像烧录到 `0x20000`，没有格式化 SD 卡。
原有 32 GB 卡挂载成功，用户文件保持不变；实机测试只操作随机命名的自建测试文件。

## 构建与主机测试

- ESP-IDF 5.5.2 构建通过。
- `transfer_files_test` 通过：128 KB 跨块写入/回读、UTF-8 路径、取消清理、短上传拒绝提交、
  完成文件不覆盖、空文件、目录与删除、路径穿越/保留文件名拦截、URL 和 JSON 编码。
- 同一文件测试在 AddressSanitizer / UndefinedBehaviorSanitizer 下通过。
- 原生 LVGL 测试通过：新增开关与地址提示、标签点击不切换状态、四方向坐标、
  亮度/息屏/Wi-Fi/导航与 80 次界面生命周期；峰值 34,960 字节，退出后空闲 44,576 字节。
- 检查控制中心渲染，使用现有完整 CJK 16 字号显示传输名称/提示，未增加字体下载依赖。

## 实机传输验收

`tools/test_file_transfer.py` 通过：

- 错误访问码返回 401，非法路径/NUL 被拒绝。
- 524,305 字节二进制文件（中文文件名）上传用时 20.3 秒，约 25 KiB/s；
  下载后 SHA-256 一致，再次上传同名内容返回 409，原内容保持一致。
- 上传期间完成 30 次页面切换、四方向旋转、亮度写入自检，无重启或 DMA 超时。
- 服务开启时，Wi-Fi 关闭和 SD 卸载请求被阻止，文件服务继续可用。
- 未完成上传断开连接后不产生目标文件；空文件上传/下载/删除通过。
- 上传连接仍打开时关闭服务，能结束 HTTP 任务并继续处理主界面命令；
  再次开启后新访问码有效、旧访问码返回 401。
- Wi-Fi 原本关闭时，打开文件服务会自动连接；关闭服务后恢复 Wi-Fi 关闭，实机验证通过。
  验收结束已将 Wi-Fi 恢复为用户原来的开启状态，文件服务关闭，界面停在控制中心。
- 传输空闲后 Grafana 自动同步成功。TLS 与服务共存时观察到最低空闲堆约 9.6 KB；
  关闭服务后恢复到约 84 KB。一次 SD 作业耗时约 69 ms，其余测试未见超过 50 ms 的作业日志。

## 限制

- 以屏幕响应为优先，传输并非高速读卡器速度；SD 卡自身写入/落盘延迟仍可能造成短暂刷新延迟。
- 传输文件期间暂缓新 Grafana 请求，空闲时继续；不承诺同时传输时刷新帧率完全不变。
- 支持 FAT16/FAT32，不支持 exFAT、文件夹创建/递归删除、USB U 盘模式或热插拔。
- 每次只处理一个网络请求；目录显示上限 256 项。大文件下载由浏览器生成 Blob 保存。
- 网络中断会清理临时文件；写入中断电/拔卡不保证文件系统安全，未做断电恢复验收。
- 临时访问码只在当前开启周期有效，串口诊断日志含访问码，只保留在本地。
