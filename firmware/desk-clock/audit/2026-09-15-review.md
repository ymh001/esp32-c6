# 固件审查与亮度死机修复（2026-09-15）

## 范围

审查当前 desk-clock 的所有手写 C/C++ 源码、头文件、构建配置、分区表、主机测试及字体生成脚本；沿故障路径检查了本地锁定版本的 LVGL 9.5、屏幕适配层、SPI 面板接口。字体位图是生成数据；没有声称逐行审计整个 ESP-IDF 和全部第三方库。

保留现有功能和用户指定的三组 WiFi。没有重写整个项目：故障集中在内存、刷新等待与任务边界，局部修复可以保留已有硬件适配。

## 故障证据

设备死机时串口每五秒报告 `IDLE (CPU 0)` 看门狗超时，当前任务是 `lvgl`。原固件 ELF 的地址解析：

- `0x42024a42` → LVGL `_calculate_draw_buf_size`
- `0x42024ca6` → `lv_draw_buf_create_ex`
- `0x4203282e` → TLSF `block_locate_free`
- `0x42024434` → `lv_draw_dispatch_layer`

本地 `sdkconfig` 实际是 64 KiB，虽然远端 `sdkconfig.defaults` 已写成 96 KiB。默认配置不会覆盖旧配置。圆角滑块在接近最小值时进入 `lv_bar.c` 的 ARGB8888 裁剪层分配路径；绘图单元分配失败后返回 idle，调度继续重试。日志和源代码共同指向此路径，而不是 WiFi 密码或背光寄存器本身。

第一轮修复后的压力测试还触发了 CPU 饥饿：`0x42021efa` 位于 LVGL `wait_for_flushing` 的默认忙等循环。测试能继续推进，但存在看门狗报警，因此该轮不计为通过。

## 已修复

| 级别 | 问题 | 修复 |
| --- | --- | --- |
| P1 | 旧配置仍使用 64 KiB LVGL 内存池 | 实际配置设为 96 KiB，并用编译期检查拒绝不足的内存配置 |
| P1 | 圆角滑块在低值时需要额外裁剪缓冲，内存不足时绘图反复重试 | 移除默认滑块样式，使用不需要离屏裁剪层的纯色直角轨道 |
| P1 | 等待屏幕 DMA 时占满单核 CPU | 用完成中断和信号量阻塞等待；超时停止运行，避免重用尚在传输的缓冲 |
| P1 | 电量服务启动失败会删除 UI 已可见的同步对象 | UI 启动前创建同步对象，创建任务失败时保留对象以便重试 |
| P2 | 每次切月删除并重新创建 42 个日期格及标签 | 复用固定对象，只更新文本和样式，减少碎片和峰值分配 |
| P2 | 亮度释放回调在持有 LVGL 锁时同步写 NVS，且忽略保存错误 | 回调提交设置副本，主循环写入；失败重试，连续修改保留最新值 |
| P2 | UI 定时器同步读取电池；SNTP 回调同步写 RTC | I2C 工作移到主循环；UI 锁只用于标签更新 |
| P2 | IMU 已记录新方向，但 UI 锁超时会永久丢失此次更新 | 每次比较期望方向和显示方向，直到成功应用 |
| P2 | IMU 初始化失败后仍被周期读取 | 增加初始化成功标记 |
| P2 | 网络状态/IP、64 位同步时间跨任务访问未同步 | 网络状态原子化；IP 和时间快照加短临界区 |
| P2 | 无效 RTC 振荡器状态仍可用于系统时间 | 拒绝 oscillator-stop 标志置位的时间 |
| P2 | I2C 写长度 `len + 1` 可溢出，空设备/缓冲未校验 | 先比较长度上限，再验证参数；寄存器读超时缩短为 100 ms |
| P2 | 无效日期可能访问星期表越界，或被当成有效农历日期 | Gregorian 日期范围校验及边界回归测试 |
| P2 | 电量接口异常字符串被解析成 0，关键字段缺失仍标为成功 | 严格检查转换和关键数值，返回失败并保留已有快照 |
| P2 | 背光写失败仍缓存为已应用，后续不重试 | 返回并检查错误，只在成功后更新缓存 |

另将 WiFi 运行时配置设为 RAM 存储，避免备用网络切换反复写 NVS；保留用户要求的重复第 2、3 项。开启任务看门狗 panic，使不可恢复任务停滞能够重启恢复，而不是永久打印报警。

## 验证记录

- 主机农历与方向测试通过；新增日期边界，并遍历 1902–2099 年所有有效日期检查结果范围。
- 第一轮板上压力测试发现 DMA 忙等报警，保留于 `ui-stress-before-dma-wait.log`，不计为通过。
- 第二轮通过：728 次亮度变化、96 次切月、四个方向、4,586 次刷新；`UI SELF TEST PASS` 出现在启动后约 89 秒。LVGL 和系统堆完整性检查均通过，没有看门狗、panic 或 DMA 超时。
- 第二轮测试结束：系统空闲堆 103,100 字节，最大连续块 39,936 字节；LVGL 稳态约 40,060 字节空闲，最大连续块 37,888 字节。
- 极限切月压力下，电池标签更新有四次 100 ms 锁等待失败，主循环跳过该次标签写入，下一轮重试；这不计为无日志错误。没有内存损坏或系统卡死。
- 农历边界/全范围测试另通过 AddressSanitizer 和 UndefinedBehaviorSanitizer。
- 正常版已刷入并通过 flash hash 校验，观察到启动后约 127 秒：连接 HLY、NTP 同步、日/周/月用电数据请求成功；未见看门狗、DMA 超时或 panic。LVGL 空闲约 39,960 字节，最大连续块 37,928 字节。
- 正常版启动的首次刷新期间有一次 100 ms UI 锁等待超时，后续继续运行；旋转路径会重试，不再永久丢失方向更新。
- 已邀请用户手动拖动亮度，完成本次记录时尚未收到物理操作反馈。

## 边界

自动测试直接驱动真实 LVGL 控件事件并刷新实际屏幕，覆盖显示/DMA/亮度命令和并发网络请求；不能替代手指触摸、拔电、弱网、I2C 硬件故障及长时间连续运行测试。HTTP 服务当前要求有界的正数 Content-Length；不支持的响应会报告更新失败，不会进入 UI 阻塞。没有注入所有内存分配失败点或故意断开传感器。
