# HA reverse-proxy transport

Screen REST control and TTS now use https://ha.hz.leaflab.cn:8888;
Assist uses wss://ha.hz.leaflab.cn:8888/api/websocket. All three HTTP clients
and the WebSocket client attach the ESP-IDF trusted CA bundle. Redirects remain
disabled for HTTP clients, and TTS accepts only HA's relative /api/tts_proxy/ path.

The private credentials header configures HA_HTTP_BASE_URL and HA_WEBSOCKET_URL.
No token or password was changed. Existing network serialization also covers TLS,
and the WebSocket is destroyed before opening the TTS HTTPS connection.

HA's Whisper and Piper connections remain internal Wyoming TCP on NAS ports
10300 and 10200. Their proposed HTTPS reverse proxies returned 502 and are not
used by the screen. A remote screen only needs access to HA's HTTPS/WSS endpoint.

Host verification: authenticated HTTPS API returned 200, WSS authenticated,
lunar/orientation/battery/text normalization and transport regression passed.

## Board validation and TLS memory

Static TLS buffers failed on-board: WSS streaming disconnected and subsequent TLS
setup returned -0x7F00 (allocation failure). Enabled ESP-IDF dynamic TLS buffers
and set outgoing record capacity to 1,024 bytes, preserving the full incoming
record limit and CA certificate verification. This releases packet buffers between
uses rather than reserving a permanent large contiguous block.

With dynamic buffers, three prerecorded state-query turns completed on the actual
screen over the configured HTTPS/WSS hostname: bits=95 for all, TTS playback
completed, end-of-turn heap 69,264 / 69,876 / 69,068 bytes. Four-device HTTPS refresh
also completed. No voice failure or unexpected reset during the observed run.

This validates the public hostname through the screen's current WiFi connection;
it does not substitute for a separate mobile-hotspot/offsite network test.

Production image 0x578390 bytes flashed successfully with boot diagnostics disabled.
Boot reached Desk clock started and completed device-state refresh over HTTPS.
